# hi-resume MVP PRD

状态：Draft
版本：0.1
更新日期：2026-08-21
产品形态：个人本地应用

## 1. 产品概述

hi-resume 是一个本地优先的个人简历管理工具。用户维护一份完整的主简历，再针对不同公司和职位创建岗位版本。岗位版本默认继承主简历，只保存与目标职位相关的修改。

产品交互参考 FlowCV 的表单编辑和实时预览体验，但不依赖在线账户或付费版本额度。

## 2. 背景与问题

针对不同职位投递时，通常需要调整：

- 个人简介和求职方向；
- 工作经历和项目的排序；
- 项目描述和成果 bullet；
- 技能顺序与关键词；
- 简历语言、长度和重点。

如果直接复制多份简历，多个版本会逐渐失去同步；如果只维护一份简历，又难以保留针对不同职位的微调结果。在线简历工具通常把多版本管理作为付费能力，且用户不希望把个人经历长期绑定在云服务中。

## 3. 产品目标

### 3.1 MVP 目标

用户可以在本地完成以下闭环：

1. 创建一份主简历；
2. 创建多个公司/职位版本；
3. 只修改岗位版本中需要调整的字段；
4. 即时查看排版效果；
5. 导出 PDF 并保存结构化备份；
6. 关闭应用后重新打开，数据仍然存在。

### 3.2 非目标

MVP 不做以下内容：

- 用户注册、登录和云端同步；
- 在线分享和协作评论；
- AI 自动改写、翻译和 JD 匹配；
- ATS 评分或“通过率”预测；
- PDF/DOCX 智能解析；
- DOCX 导出；
- 求职进度管理和邮件投递；
- 多模板市场和自由画布排版。

## 4. 目标用户与典型场景

### 4.1 目标用户

第一阶段只服务个人用户，尤其是：

- 需要高频投递不同职位的求职者；
- 已经有一份成熟简历，但需要持续微调的人；
- 重视隐私、备份和本地数据控制的人。

### 4.2 核心场景

用户有一份完整主简历，准备申请一家公司的产品经理职位：

1. 新建岗位版本，填写公司和职位；
2. 主简历内容自动继承；
3. 将最相关的项目移动到前面；
4. 修改个人简介和两条工作经历；
5. 调整技能顺序；
6. 查看一页或多页预览；
7. 导出 `公司-职位-姓名.pdf`。

## 5. 核心产品模型

### 5.1 主简历

主简历是个人经历的完整内容库，不以某一个职位为目标。它包含用户愿意长期维护的全部经历和可复用内容。

### 5.2 岗位版本

岗位版本是主简历的一个视图和覆盖层，而不是完整复制品。它包含目标职位元信息，以及被用户明确修改的字段。

```text
岗位版本最终内容 = 主简历内容 + 岗位版本覆盖值 + 岗位版本显示/排序设置
```

### 5.3 字段状态

每个可调整字段需要能表达：

- `inherited`：继承主简历；
- `overridden`：岗位版本已修改；
- `hidden`：当前版本隐藏；
- `orphaned`：主简历中的来源字段已被删除，需要用户处理。

## 6. 功能范围

### 6.1 P0：必须完成

#### A. 本地工作区

- 首次打开时创建本地工作区；
- 无账号、无后端、无必需网络请求；
- 自动保存编辑结果；
- 显示最近保存时间；
- 提供 JSON 导入和导出；
- 导入数据前进行格式校验；
- 数据结构带 `schemaVersion`，为未来迁移预留空间。

#### B. 主简历编辑

支持以下标准区块：

- 基本信息；
- 个人简介；
- 工作经历；
- 项目经历；
- 教育经历；
- 技能；
- 语言；
- 自定义区块。

每个区块支持：

- 新增、编辑、删除；
- 显示/隐藏；
- 区块排序；
- 区块内条目排序；
- 删除前确认。

#### C. 岗位版本管理

- 从主简历创建岗位版本；
- 填写公司、职位、地点、状态和备注；
- 可选保存 JD 原文，仅作为参考资料；
- 创建、重命名、复制、归档和删除岗位版本；
- 列表显示更新时间和当前模板；
- 明确标识当前编辑的是主简历还是岗位版本。

#### D. 继承与覆盖

- 岗位版本默认继承主简历；
- 修改字段时自动生成覆盖值；
- 字段旁显示“继承中”或“已修改”；
- 一键恢复为主简历内容；
- 支持隐藏当前版本中的区块或条目；
- 支持岗位版本独立调整区块和条目顺序；
- 主简历新增内容可以被岗位版本继续继承；
- 主简历删除来源内容时，岗位版本需要显示待处理提示，不静默丢失修改。

#### E. 编辑器与预览

桌面端采用三栏布局：

- 左栏：区块导航和版本状态；
- 中栏：表单编辑；
- 右栏：A4 实时预览。

最低交互要求：

- 输入后预览即时更新；
- 编辑区支持多行文本和 bullet 列表；
- 预览区在桌面端保持稳定的 A4 比例；
- 支持 A4 和 Letter 页面尺寸；
- 支持一页和多页内容；
- 编辑过程中不因为预览刷新丢失输入。

#### F. 导出

- 浏览器/Chromium 打印为 PDF；
- PDF 为文本型内容，不使用整页图片；
- 自动建议文件名；
- 导出前显示当前岗位版本名称；
- 导出 JSON 作为完整备份；
- 导入 JSON 后可以继续编辑和导出。

#### G. 基础恢复能力

- 最近一次数据快照；
- 最近若干次编辑快照；
- 撤销和重做；
- 导出前不覆盖原始数据；
- 删除岗位版本前二次确认。

### 6.2 P1：MVP 后优先考虑

- 主简历与岗位版本差异视图；
- 点击预览区定位到对应编辑字段；
- 字段级版本历史；
- 关键词高亮，但不进行 AI 评分；
- 多语言简历；
- 更丰富的字体、颜色和间距设置；
- 可复用的 bullet 内容库；
- 简单的封面信模板。

### 6.3 P2：暂不承诺

- AI 改写和 JD 匹配；
- ATS 评分；
- PDF/DOCX 导入；
- DOCX 导出；
- 云同步和多设备；
- 分享链接；
- 求职追踪器；
- 模板市场。

## 7. 页面与交互

### 7.1 工作区首页

显示：

- 主简历入口；
- 岗位版本卡片列表；
- 最近编辑时间；
- 公司、职位和投递状态；
- 新建岗位版本；
- 导入/导出工作区。

空状态需要提供明确入口：

> 创建你的主简历，之后可以针对不同职位创建多个版本。

### 7.2 编辑页面

顶部显示：

- 当前版本名称；
- 当前状态；
- 最近保存时间；
- 导出 PDF；
- 返回工作区。

字段编辑时使用轻量提示：

- “继承自主简历”；
- “此版本已修改”；
- “恢复主简历内容”。

避免使用技术化词汇如 overlay、patch、merge 直接暴露给普通用户。

## 8. 数据模型草案

内部模型需要给每个区块和条目分配稳定 ID，避免用户调整顺序或修改主简历后无法定位覆盖内容。

```ts
type Workspace = {
  schemaVersion: number
  master: ResumeDocument
  variants: ResumeVariant[]
  settings: WorkspaceSettings
}

type ResumeVariant = {
  id: string
  name: string
  company?: string
  role?: string
  location?: string
  status: "draft" | "applied" | "interviewing" | "closed"
  jobDescription?: string
  overrides: Record<string, unknown>
  hiddenPaths: string[]
  orderOverrides: Record<string, string[]>
  createdAt: string
  updatedAt: string
}
```

建议使用 JSON Resume 的标准字段作为互操作参考，但内部模型需要增加稳定 ID、版本覆盖、隐藏状态、排序和岗位元信息。

## 9. 非功能需求

### 隐私

- 默认数据不离开本机；
- 默认不加载第三方分析脚本；
- AI 或外部服务未来必须显式开启；
- 导入和导出均由用户主动操作。

### 性能

- 普通编辑输入后预览更新应接近即时；
- 打开已有工作区不应明显卡顿；
- 典型个人简历规模下不限制区块数量；
- PDF 导出前应完成字体和分页检查。

### 可恢复性

- JSON 是可读、可迁移的备份格式；
- 数据结构必须支持版本迁移；
- 本地存储损坏时，用户仍可通过 JSON 恢复。

## 10. MVP 验收标准

### 核心闭环

- 新用户可以在 10 分钟内创建主简历；
- 用户可以在 30 秒内创建岗位版本；
- 岗位版本能继承主简历未修改字段；
- 修改字段后仅当前版本发生变化；
- 恢复字段后内容与主简历一致；
- 主简历新增字段不会破坏现有岗位版本；
- 删除来源字段后不会静默丢失岗位版本覆盖值。

### 输出与数据

- 预览内容和导出 PDF 内容一致；
- PDF 文本可以被选择和复制；
- 导出的 JSON 可以重新导入；
- 关闭并重新打开应用后数据仍在；
- 可以通过备份文件恢复完整工作区。

### 质量底线

- 一页简历不出现明显截断；
- 两页简历分页稳定；
- 关键操作有成功、失败和恢复提示；
- 删除操作不可误触完成；
- 不依赖登录或在线服务才能使用核心功能。

## 11. 实施顺序

### Phase 0：领域模型与静态预览

- 定义数据结构和稳定 ID；
- 完成主简历表单；
- 完成一个模板的 HTML/CSS 预览；
- 用本地固定 JSON 验证渲染。

### Phase 1：本地持久化与岗位版本

- 接入 IndexedDB；
- 实现主简历和岗位版本；
- 实现字段覆盖、恢复、隐藏和排序；
- 实现自动保存和 JSON 备份。

### Phase 2：导出与体验打磨

- 完善打印样式和分页；
- 加入撤销/重做；
- 完成首页和空状态；
- 完成关键流程测试；
- 使用真实投递场景验证。

## 12. 成功指标

个人使用场景下，MVP 达到以下结果即可进入下一阶段：

- 可以连续维护至少 5 个岗位版本；
- 新建岗位版本不需要复制粘贴整份简历；
- 修改主简历后，岗位版本仍然可控地继承更新；
- 用户能快速识别某个版本改过哪些内容；
- 每个岗位版本都能稳定导出可投递 PDF；
- 不依赖 FlowCV 或其他在线服务完成完整流程。

## 13. 关键风险与决策

### 风险：继承关系难以理解

决策：以“继承中/此版本已修改/恢复主简历”这种用户语言呈现，不向用户展示底层 patch 或 merge 概念。

### 风险：PDF 排版投入过大

决策：MVP 只提供一个稳定模板，先保证文本、分页和导出质量，再扩展视觉样式。

### 风险：本地数据丢失

决策：自动保存、快照和 JSON 导出必须进入 P0，而不是以后再补。

### 风险：功能扩张

决策：任何不能直接帮助“维护主简历、创建岗位版本、调整并导出”的功能，默认放入 P1 或 P2。
